# Move Storm Imagery to Cloudflare R2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Get GitHub Pages deploys working again by moving the 17GB `images/{ian,ida,harvey,michael}` storm imagery out of the repo and onto Cloudflare R2, then strip the historical blobs from `.git`.

**Architecture:** A one-off Python script rewrites the `images/{storm}/...` URL patterns in the catalog JSON files to `https://img.weathercanvas.com/{storm}/...`. Imagery is uploaded to R2 with `rclone`, one storm directory at a time. Git history is rewritten with `git-filter-repo` to remove the historical image blobs, then force-pushed. `images/static/` (UI icons, 12M) is untouched throughout — it stays in the repo and is never rewritten (its patterns use the literal prefix `images/static/`, not `images/{storm}/`).

**Tech Stack:** Python 3 (stdlib only), rclone, git-filter-repo (already installed at `/usr/local/bin/git-filter-repo`)

**Reference spec:** `docs/superpowers/specs/2026-08-12-images-to-r2-design.md`

## Prerequisites (manual, before Task 3)

Before Task 3 (upload), you must do this in the Cloudflare dashboard — no CLI/API access available for these steps:

1. Create an R2 bucket named `weathercanvas-images`, enable public access.
2. Bind custom domain `img.weathercanvas.com` to the bucket (Cloudflare auto-creates the DNS CNAME since the domain is already on Cloudflare).
3. Generate an R2 API token (S3-compatible access key + secret) under R2 → Manage API Tokens.

Keep the access key/secret ready for Task 3's `rclone config` step — enter them at the interactive prompt, not into any file.

### Task 1: Write the catalog URL rewrite script

**Files:**
- Create: `rewrite_image_urls.py`

Exact `images/{storm}/` occurrence counts confirmed by grep (used as test assertions below):

| File | Count |
|---|---|
| `json/catalog.json` | 38 |
| `json/catalog_2d.json` | 124 |
| `json/catalog_3d.json` | 8 |
| `json/catalog_diag.json` | 2 |
| `json/catalog_analysis.json` | 36 |
| **Total** | **208** |

`images/static/` occurrences (must NOT be touched): 4 in `catalog_3d.json`, 1 in `catalog_analysis.json`, 4 in `catalog.json` (`images/static/` is a different literal prefix than `images/{storm}/`, so a plain substring replace of `images/{storm}/` never matches it).

- [ ] **Step 1: Write the script**

```python
#!/usr/bin/env python3
"""Rewrite images/{storm}/ URL patterns in catalog JSON files to the R2 CDN URL.

images/static/ patterns are untouched (different literal prefix) since those
assets stay in the repo.
"""
import json
import sys
from pathlib import Path

REPO_ROOT = Path(__file__).resolve().parent
OLD_PREFIX = "images/{storm}/"
NEW_PREFIX = "https://img.weathercanvas.com/{storm}/"
CATALOG_FILES = [
    REPO_ROOT / "json" / "catalog.json",
    REPO_ROOT / "json" / "catalog_2d.json",
    REPO_ROOT / "json" / "catalog_3d.json",
    REPO_ROOT / "json" / "catalog_diag.json",
    REPO_ROOT / "json" / "catalog_analysis.json",
]


def main():
    dry_run = "--dry-run" in sys.argv
    total = 0
    for path in CATALOG_FILES:
        original = path.read_text()
        count = original.count(OLD_PREFIX)
        total += count
        if count == 0:
            print(f"{path.name}: 0 replacements")
            continue
        rewritten = original.replace(OLD_PREFIX, NEW_PREFIX)
        json.loads(rewritten)  # fail loud if this broke JSON validity
        print(f"{path.name}: {count} replacements")
        if not dry_run:
            path.write_text(rewritten)
    suffix = " (dry run, no files written)" if dry_run else ""
    print(f"Total: {total} replacements{suffix}")


if __name__ == "__main__":
    main()
```

- [ ] **Step 2: Run in dry-run mode and verify counts**

Run: `python3 rewrite_image_urls.py --dry-run`

Expected output (order matches `CATALOG_FILES`):
```

catalog_2d.json: 124 replacements
catalog_3d.json: 8 replacements
catalog_diag.json: 2 replacements
catalog_analysis.json: 36 replacements
Total: 208 replacements (dry run, no files written)
```

If any count differs, stop and diff `json/catalog*.json` against what the counts table above assumed — the catalog may have changed since this plan was written.

- [ ] **Step 3: Confirm no files were modified by the dry run**

Expected: no output (clean).


### Task 6: Rewrite git history to remove historical image blobs

**This is destructive to commit SHAs. Confirmed solo repo (no other clones/collaborators) — safe to force-push.**

- [ ] **Step 1: Confirm working tree is clean before rewriting**

```bash

```

Expected: no output. If anything is uncommitted, stop and commit or stash it first.

- [ ] **Step 2: Record current `.git` size for before/after comparison**

```bash

```

- [ ] **Step 3: Run git-filter-repo to strip `images/` from all history**

```bash

```

Expected: prints a summary ("Parsed N commits" / "New history written"), exits 0. Note: this also removes `images/static/` from history — restored fresh in Step 5.

`--force` is required because filter-repo refuses to run on a repo that wasn't freshly cloned by default; this is expected and safe here.

- [ ] **Step 4: Verify `.git` shrank**

```bash

```

Expected: dramatically smaller than the Step 2 measurement (should be well under 1GB).

- [ ] **Step 6: Re-add the remote (filter-repo removes it as a safety measure) and force-push**


Expected: push succeeds. GitHub will show a rewritten-history warning in the UI for the branch — expected and fine for a solo repo.
